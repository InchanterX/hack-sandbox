# Дашборд продаж Capibara

Дашборд показывает динамику продаж доставленных заказов и вклад продавцов и категорий. Это позволяет руководителю маркетплейса оценивать рост и состав продаж, а менеджеру продавцов — выбирать продавцов и категории для дальнейшего изучения. Отдельный блок повторных покупок помогает CRM-менеджеру оценить возвращаемость. Это концепция, а не готовая визуализация.

Дашборд отвечает на вопросы:

- Как меняются выручка и число доставленных заказов по месяцу оформления?
- Каков средний чек и какие продавцы и категории дают выручку?
- Сколько покупателей оформляли заказы повторно и какова их доля?

## Показатели и расчёт

Период задаётся по `purchased_at` как полуоткрытый интервал: начало включено, конец исключён. Месяц — месяц оформления, а не доставки. Продажи включают только заказы со статусом `core.order_statuses.counts_as_revenue = true` (сейчас `delivered`). Представления `core.revenue_items` и `core.revenue_orders` уже применяют этот фильтр; второе содержит только заказы с позициями. Значения при пустом знаменателе показываются как «нет данных».

| Показатель | Формула и уровень расчёта | Источники core |
|---|---|---|
| Выручка | `SUM(revenue)` по позициям за период; цена товара без доставки. Срезы: месяц, продавец, категория. | `revenue_items`; для категории — `products` по `product_id`, для продавца и его города/штата — `sellers` по `seller_id` |
| Доставленные заказы | `COUNT(*)` строк за период; уровень — заказ. По месяцу сумма даёт итог за период. | `revenue_orders` |
| Средний чек | `SUM(order_check) / COUNT(*)`; уровень — заказ, чек включает цену и доставку всех его позиций. | `revenue_orders` |
| Выручка продавца и топ-10 | `SUM(revenue)` его позиций; уровень — позиция, затем продавец. Ранжировать по выручке по убыванию, при равенстве — по `seller_id`. | `revenue_items`, `sellers` |
| Выручка категории и доля | `SUM(revenue)` позиций категории; доля = 100 × выручка категории / выручка всех категорий в выбранном периоде. Уровень — позиция, затем категория. Отсутствующую категорию и отсутствующую карточку показывать как `unknown`, не теряя выручку. | `revenue_items`, `products` через `LEFT JOIN` |
| Покупатели | `COUNT(DISTINCT customer_unique_id)` среди заказов за период во всех статусах; уровень — покупатель. Пустой идентификатор исключён. | `orders` |
| Вернувшиеся покупатели и доля | Для каждого покупателя посчитать `COUNT(DISTINCT order_id)` за период во всех статусах; вернувшиеся — с числом заказов > 1. Доля = 100 × вернувшиеся / все покупатели периода. Уровень — покупатель. | `orders` |

Повторная покупка здесь означает два заказа **внутри выбранного периода**, а не возврат относительно всей истории. Поэтому при смене периода состав вернувшихся меняется. Метрики покупателей включают все статусы, в отличие от блока продаж; это соответствует определению `mart.a4_customers` на всей истории. Для сопоставления с ответами блока А использовать те же периоды, в частности для помесячной динамики — сентябрь 2016 — август 2018; месяцы без заказов показывать нулями, как в `mart.a1_monthly_revenue`.

## Что нельзя складывать по срезам

- **Средний чек**: сумма средних не является средним всего периода. Пересчитать из суммы чеков и числа заказов; при объединении месяцев можно взвесить средние по числу заказов.
- **Доли категорий и вернувшихся покупателей**: проценты с разными знаменателями не складываются для получения общей доли. Пересчитать числитель и знаменатель на нужном уровне. Доли категорий внутри одного полного разбиения с общим знаменателем складываются до 100% с возможной погрешностью округления.
- **Уникальные и вернувшиеся покупатели**: один человек может присутствовать в нескольких месяцах, категориях или у разных продавцов. Дедуплицировать по `customer_unique_id` и заново оценить число заказов на объединённом периоде; сумма месячных вернувшихся не учитывает покупателя с одним заказом в каждом месяце.
- **Число заказов по продавцам или категориям**: один заказ может содержать позиции нескольких продавцов или категорий. Для общего числа считать разные `order_id` на объединении, а не складывать значения срезов.

Выручку можно суммировать по непересекающимся месяцам, продавцам и категориям, если каждая позиция учтена ровно один раз, включая `unknown`. Топ-10 — только часть продавцов и не равен общей выручке.

## Раскладка экрана

1. Сверху — выбор периода и подпись о статусах и дате оформления.
2. Карточки: выручка, доставленные заказы, средний чек; рядом отдельный блок покупателей и доли вернувшихся с пометкой «все статусы».
3. График по месяцам: выручка и число заказов с отдельными шкалами.
4. Две таблицы: топ-10 продавцов с городом и штатом; категории с выручкой и долей, включая `unknown`.
