# PLAN

## Модули

Реализовать только Must последовательно одним исполнителем. Архитектура: React SPA, Go API с воркерами в одном процессе и PostgreSQL 17. Обработчики отвечают за HTTP, сервисы — за бизнес-логику, stores — за SQL; интерфейсы объявляются у потребителей.

| Модуль / файлы | Ответственность | Зависит от |
|---|---|---|
| `contracts/`, scaffold | OpenAPI 3.1, генерация Go/TS, контрактные тесты, manifests зависимостей, маршруты и конфигурация проверок | Бриф, `DECISIONS.md` |
| `server/migrations/` | `users`, `sessions`, `tasks`, ограничения, индексы, встроенные goose-миграции | Модель данных |
| `server/internal/calc` | Лексер, рекурсивный спуск, AST, вычисление, callback задержки каждой бинарной операции | Стандартная библиотека |
| `server/internal/auth` | Регистрация, вход, выход, `/api/me`, сессии, Bearer middleware | БД, bcrypt, общие HTTP-ответы |
| `server/internal/tasks` | CRUD только собственных задач | `calc`, пользователь, БД |
| `server/internal/queue` | Захват, вычисление, результат, восстановление, остановка воркеров | `calc`, таблица `tasks` |
| `server/internal/server`, `cmd/server` | Маршруты, ошибки, healthz, env, миграции, композиция и жизненный цикл | Backend-модули |
| `web/src/api`, `auth`, экраны | Типизированный клиент, сессия, защищённые маршруты, формы, список | OpenAPI, API |
| Dockerfiles, compose, `deploy/` | Локальная среда, проверки, production-образы и кластер | Точки входа приложения |
| `tests/e2e/` | Полный сценарий демо и проверки API | Backend и Postgres |

Стек: Go 1.26, `net/http`, pgx, goose, slog; React 19, TypeScript strict, React Router 7, TanStack Query 5, `openapi-fetch`, CSS Modules. `queue` работает с таблицей напрямую через свой store, не зависит от HTTP-обработчиков `tasks`.

Порядок зависимостей: контракт + scaffold + миграции → calc → auth → tasks → queue и жизненный цикл сервера → frontend → production-развёртывание → полная проверка → релиз.

Оценочный бюджет — 600 минут (10 часов) одного исполнителя, включая резерв; числового срока в `brief/02_scope.md` нет. Оценки включают локальные тесты модулей.

| Этап | Минуты | Результат |
|---|---:|---|
| Контракт и scaffold | 80 | Генерация Go/TS, миграции, compose `db/server/web/dev`, healthz с проверкой БД |
| `calc` | 35 | Грамматика, вычисление, ошибки, округление, табличные тесты |
| `auth` | 45 | Регистрация, вход, выход, проверка сессии |
| `tasks` | 45 | CRUD, изоляция, ограничения статусов |
| `queue` и композиция | 55 | Два воркера, задержки, восстановление, ограниченное завершение |
| Frontend | 80 | Три экрана, polling, редактирование, удаление, состояния, адаптивность |
| Production-конфигурация | 45 | Образы, nginx, Kustomize, probes, PVC, HTTPRoute |
| Полная проверка | 65 | Проверки, API e2e, гонки, restart |
| Релиз и браузерное демо | 30 | Публичный URL и ручная проверка |
| Резерв | 60 | Исправления Must, сборки и инфраструктуры |

В начале проверить namespace, Secret `db` и ключ `POSTGRES_PASSWORD`, StorageClass `local-path`, Gateway `default/home-gateway` и возможные ограничения Pod Security для Postgres. При отсутствии внешних предпосылок отметить их и продолжить независимую работу; публичный релиз не считать завершённым до их появления.

Привести `tasks.yaml` к реальным задачам и проверкам областей, заменить образ `app` на `server` и `web`. Общие файлы закрепить за scaffold по `brief/05_conventions.md`: контракт, миграции, manifests зависимостей, маршруты, router, compose, объявления секретов и прочие перечисленные там файлы. Генерированные файлы менять и коммитить вместе с контрактом.

### Фиксированное поведение

1. Перенести все десять операций `brief/06_contracts.md` с методами, путями, статусами и телами в OpenAPI 3.1; закрепить `oapi-codegen v2.8.0`, проверить генерацию первой. UUID, UTC/RFC 3339, nullable `result/error`, пустой список `{"items":[]}`. Создать индексы `(status, created_at)` и `(user_id, created_at DESC)`. Встроить миграции через Go-пакет внутри `server/migrations/` для build context сервера.
2. Логин `[a-z0-9_-]{3,32}` без изменения регистра; пароль 8–72 байта UTF-8, frontend измеряет `TextEncoder`. Выражение длиной 1–200 символов; нарушение — 422 `validation_error`, запрещённые символы и неверная грамматика — 422 `syntax_error`, также при PATCH. Все `error.message` русские.
3. Число `[0-9]+(\.[0-9]+)?`: `007` допустимо, `.5` и `5.` нет. Приоритет унарного минуса, затем `* /`, затем `+ -`; бинарные операции левоассоциативны. Допустимы `--5` и выражения без операций. Деление на ноль выявляется при вычислении. Округлять только конечный результат до десяти знаков, нормализовать `-0`; проверять конечность арифметики и округления. Переполнение — `failed`, код `overflow`, текст «переполнение»; закрепить в контракте как решение этого плана.
4. Bcrypt; непрозрачный токен из 32 случайных байтов в base64url, хранить SHA-256 и срок действия (по умолчанию 24 часа). Регистрация сразу возвращает сессию, logout удаляет её; middleware помещает пользователя в context с типизированным ключом.
5. Все пользовательские SQL-запросы ограничены `user_id`, список — `created_at DESC`. Чужой, отсутствующий или некорректный UUID — 404. PATCH/DELETE блокируют принадлежащую пользователю строку в store-транзакции, проверяют статус и выполняют условную мутацию. PATCH только для `queued`, DELETE запрещён для `running`, иначе соответствующий 409; PATCH сохраняет `created_at`.
6. Захват — атомарный шаблон архитектуры с `FOR UPDATE SKIP LOCKED`, сортировкой по `created_at` и `RETURNING expression`; завершить транзакцию до вычисления и вычислять возвращённое выражение. Defaults: два воркера, 700 мс на бинарную операцию, 300 мс idle polling; таймеры отменяются через context. Записывать `done/result` или `failed/error` и всегда `finished_at`. После миграций при старте переводить `running` в `queued`, очищая поля исполнения.
7. Повторять подключение к БД с ограниченным ожиданием до 60 секунд; DSN собирать в Go с корректным экранированием пароля. По SIGTERM прекратить новые захваты, завершить HTTP-запросы, дать вычислениям до 10 секунд, затем отменить их; прерванные задачи оставить для восстановления.
8. Токен в `localStorage`, единый клиент; при 401 защищённого запроса очистить сессию и пользовательский кэш, перейти на `/login`, ошибку входа показать в форме. При выходе и смене аккаунта отменять запросы и очищать пользовательский кэш. Использовать пользовательский ключ задач, polling 1000 мс и invalidation после мутаций. Показывать результат `0`, loading/empty/error, повтор и конфликты 409; редактирование только в `queued`, удаление скрыто в `running`. Соблюсти дизайн-токены, ширину 720 px, карточки до 640 px и доступность с клавиатуры.
9. Server: сборка на `golang:1.26`, runtime distroless nonroot; web: Node 24 и nginx-unprivileged 1.29, SPA fallback без проксирования API. Postgres StatefulSet, PVC 1 Gi, Services, Deployments, ConfigMap, HTTPRoute `/api` → `server:8080` с сохранением префикса и `/` → `web:8080`. Ресурсы и probes — строго по `brief/08_deploy.md` и devops-правилам. Одна реплика server, `Recreate`, `terminationGracePeriodSeconds: 30`. В `deploy/secrets.yaml` объявить только имя и ключ секрета; значение создаёт человек. Не создавать запрещённые AppProject объекты; теги образов подставляет pipeline.

### Проверка и завершение

Все автоматические проверки выполнять в compose-сервисе `dev`, не вызывая внутри него Docker:

```sh
cd server && golangci-lint run ./...
cd server && go build ./...
cd server && go test -race -tags=integration ./...
cd web && npm ci
cd web && npm run lint
cd web && npm run typecheck
cd web && npm test -- --run
cd web && npm run build
kustomize build deploy/overlays/demo > /dev/null
hadolint server/Dockerfile web/Dockerfile Dockerfile.dev
npm --prefix tests/e2e test
```

Команды с `cd` запускать из корня отдельно. Подключить контрактные тесты scaffold к проверкам явной рабочей командой. Заглушки могут проходить сборку и проверку схем, семантическая приёмка — на законченных обработчиках.

Проверить парсер: приоритет, ассоциативность, унарный минус, десятичные числа, синтаксис, ноль, округление, переполнение; stores: принадлежность, порядок списка и очереди, PATCH/DELETE против захвата; воркеры: задержки, восстановление, завершение, `-race` и `goleak`; UI: формы, 409/422, состояния запросов, действия по статусу и смену аккаунта.

API e2e проходит все девять шагов демо, 401/404/409/422, результаты `11`, `2`, `93`, деление на ноль и принудительный restart. Он сам собирает и запускает сервер с `OP_DELAY_MS=50`, использует уникальные логины, достаточно длинные блокирующие выражения и ограниченное ожидание состояний, затем останавливает процесс. Ручной прогон на публичном URL проверяет маршруты, мобильный вид и обновление статусов за две секунды.

## Где планы совпали

Claude и member-3 предложили три сервиса, перечисленные backend-модули, контракт и миграции до реализации, PostgreSQL-очередь с `SKIP LOCKED`, сохранение `created_at` при PATCH и вычисление выражения из атомарного захвата. Оба предусматривают русские ошибки, строгие числа, пароль 8–72 байта UTF-8, polling раз в секунду, одну реплику с `Recreate`, тесты гонок, изоляции, восстановления и остановки. Member-2 лишь повторил инструкцию и самостоятельного ответа для сравнения не дал.

## Где планы разошлись и что выбрано

- OpenAPI: сохранить 3.1 по контракту, закрепить `oapi-codegen v2.8.0`, поддерживающий 3.1 и nullable-типы; не понижать до 3.0.3.
- Сроки 4 и 5–6 часов предполагали параллельную работу; принять оценку 10 часов последовательно, включая час резерва, не выдавая её за срок брифа.
- Все Nice исключены; резерв — для Must и релиза. Карточки до 640 px обязательны.
- Окно редактирования — принятое решение Q1/Q7 в `DECISIONS.md`, а не предположение; `ASSUMPTIONS.md` пуст.
- В гонке PATCH/claim возможны два последовательных успеха: PATCH затем claim. Проверять сохранение принятого изменения; если первым claim, PATCH возвращает 409.
- Защита от переполнения с `overflow` — новое решение этого плана, не ранее принятое человеком решение.

## Риски и как их снимаем

| Риск | Снижение |
|---|---|
| Окно редактирования исчезает | По Q1/Q7 занять оба воркера двумя длинными выражениями, дождаться `running`, затем создать и изменить целевую задачу; то же в e2e |
| PATCH принят, но вычисляется старое выражение | Вычислять `expression` из claim `RETURNING`; проверить оба порядка гонки |
| Новый pod сбрасывает работу старого | Одна реплика, `Recreate`; не запускать второй сервер на той же тестовой очереди |
| Нестабильные временные тесты | `testing/synctest`, управляемые таймеры, ограниченный polling в e2e |
| Проверки вмешиваются друг в друга | Отдельные схемы интеграционных тестов; последовательный e2e с собственным процессом сервера |
| Генерация или проверки ломаются поздно | Генерация в начале, реальные проверки каждого завершённого модуля |
| Кластер блокирует релиз | Ранняя проверка namespace, Secret, StorageClass, Gateway и политики Postgres |

## Out of scope

Все Nice: фильтр, счётчики, SSE. Также OAuth, email и восстановление пароля, роли и профиль, расширенная арифметика, отдельный worker-сервис, брокеры, WebSockets, пагинация, refresh-токены, очистка просроченных сессий, i18n, тёмная тема, мобильное приложение, rate limiting, captcha, аудит, браузерные e2e, seed-данные, внешние SaaS, телеметрия и AI/ML.
