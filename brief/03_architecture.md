# Архитектура

## Компоненты

- **web** — SPA на React, собирается в статику и отдаётся nginx (непривилегированный образ). В браузере
  ходит в API по тому же домену, путь `/api` — без CORS.
- **server** — Go: HTTP API (`/api/...`) и пул воркеров очереди в одном процессе. Миграции goose применяет
  сам при старте.
- **db** — PostgreSQL 17: пользователи, сессии, задачи; очередь — таблица `tasks`.

Маршрутизация в кластере: HTTPRoute `sandbox.hack.faberge-eggs.ru`, `/api` → `server:8080`, `/` → `web:8080`.
Локально (compose) Vite dev-сервер проксирует `/api` на `server`.

## Очередь

- Создание задачи — `INSERT` со статусом `queued`.
- Воркер берёт задачу так: `UPDATE tasks SET status='running', started_at=now() WHERE id = (SELECT id FROM
  tasks WHERE status='queued' ORDER BY created_at LIMIT 1 FOR UPDATE SKIP LOCKED) RETURNING ...`.
- Число воркеров — `WORKERS` (по умолчанию 2), задержка на одну бинарную операцию — `OP_DELAY_MS`
  (по умолчанию 700). Простой воркер опрашивает очередь раз в `POLL_INTERVAL_MS` (по умолчанию 300).
- Изменение и удаление задачи идут в той же транзакционной логике: `UPDATE ... WHERE status='queued'`, чтобы не
  было гонки с воркером (0 строк → 409).
- При старте сервер переводит все `running` в `queued` (прошлый процесс умер посреди вычисления).
- Остановка: по SIGTERM воркеры дорабатывают текущую задачу (до 10 с) и выходят; HTTP-сервер — graceful shutdown.

## Принятые решения (ADR-лайт)

| # | Решение | Почему | Альтернативы |
|---|---|---|---|
| 1 | Очередь в Postgres (`FOR UPDATE SKIP LOCKED`) | одна зависимость вместо двух, транзакции с изменением задачи | Redis, RabbitMQ — лишний сервис |
| 2 | Воркеры в процессе сервера | один образ, одна реплика достаточно для демо | отдельный сервис-воркер |
| 3 | Непрозрачные токены сессий в БД (sha256 от токена) | выход = удаление строки; не нужен ключ подписи | JWT — нужен секрет и отзыв |
| 4 | Свой парсер (рекурсивный спуск) | точный контроль ошибок и задержки по операциям | `eval`-библиотеки |
| 5 | Живые статусы опросом раз в 1 с | просто и надёжно через любой прокси | SSE (Nice), WebSocket |
| 6 | Числа — `float64`, ответ округляется до 10 знаков, `-0` → `0` | достаточно для демо | `big.Rat` |

## Ограничения

- Одна реплика сервера (воркеры в процессе); нагрузка — единицы пользователей.
- Браузеры: последние Chrome, Firefox, Safari; ноутбук и телефон.
