# Продукт

## Что и зачем

Calc Queue — веб-сервис, который вычисляет арифметические выражения в фоновой очереди. Пользователь входит
под своим логином, отправляет выражение (например, `2 + 3 * (4 - 1)`), задача встаёт в очередь, воркер
сервера вычисляет её с искусственной задержкой на каждую операцию, а пользователь в реальном времени видит,
как его задачи проходят статусы `queued → running → done` (или `failed`). Задержка нужна, чтобы очередь
была видна глазами.

## Пользователи и роли

- **Пользователь** — регистрируется по логину и паролю, видит и меняет только свои задачи.
- Ролей и админки нет.

## Сценарий демо

1. Открываем `https://sandbox.hack.faberge-eggs.ru` — без входа видим страницу входа; на ней ссылка
   «Регистрация».
2. Регистрируем пользователя `alice` с паролем `alice-pass-1`; после регистрации сразу попадаем в список задач
   (пустой, с подсказкой «Задач пока нет»).
3. Отправляем выражение `2 + 3 * (4 - 1)` — в списке появляется задача со статусом «в очереди».
4. Быстро отправляем ещё две: `(10 - 4) / 3` и `7 / (2 - 2)`. Видно, что задачи ждут в очереди и по одной
   переходят в «выполняется» (воркеров меньше, чем задач).
5. Не обновляя страницу, видим результаты: `11`, `2`, а у третьей — статус «ошибка» и текст
   «деление на ноль».
6. Отправляем `100 / 7 + 1`, пока она «в очереди», нажимаем «Изменить» и меняем на `100 - 7`; задача
   выполняется уже с новым выражением и даёт `93`.
7. Отправляем некорректное `2 + * 3` — форма сразу показывает ошибку «синтаксическая ошибка», задача не
   создаётся.
8. Удаляем задачу с ошибкой — она исчезает из списка.
9. Выходим, регистрируем `bob` — его список пуст: задач `alice` он не видит. Входим снова под `alice` —
   её задачи на месте.

## Критерии приёмки демо

- [ ] Без входа любая страница, кроме входа и регистрации, перенаправляет на вход; API без токена отвечает 401.
- [ ] Повторная регистрация занятого логина — понятная ошибка «логин занят», API — 409.
- [ ] Статус задачи в интерфейсе обновляется без перезагрузки страницы не позже чем за 2 с.
- [ ] Результаты сценария точные: `2 + 3 * (4 - 1)` = `11`, `(10 - 4) / 3` = `2`, `100 - 7` = `93`.
- [ ] Деление на ноль → статус `failed` с кодом `division_by_zero`, сервис продолжает работать.
- [ ] Синтаксическая ошибка отклоняется при создании (API 422, код `syntax_error`), в очередь не попадает.
- [ ] Изменить можно только задачу в `queued`; для остальных API отвечает 409, а кнопка в интерфейсе скрыта.
- [ ] Удалить нельзя только задачу в `running` (409); остальные удаляются.
- [ ] Пользователь не видит и не может изменить чужие задачи: чужой id — 404.
- [ ] После перезапуска сервера задачи, которые были `running`, снова в `queued` и досчитываются.

## Данные для демо

Seed-данные не нужны: пользователей и задачи создаём в ходе демо.
