# Release smoke contracts

- `openapi.yaml`: OpenAPI 3.1, итоговые JSON-ответы после S5. `/not-a-route`
  представляет неизвестный GET request target; это не новый специальный маршрут.
- `types.py`: типы стандартной библиотеки Python для тех же трёх ответов.
  Это описание контракта, не новая runtime-зависимость для `app/server.py`.
- `schema.sql`: явный контракт отсутствия БД, только комментарии; не выполнять
  миграции, не добавлять таблицы или хранилище.

Сначала S4 сохраняет имеющиеся контрактные проверки здоровья и неизвестного
пути в `tests/contract/test_http.py`. Сообщение корня на этой стадии ещё `seed`.
После S4 контрактные тесты заморожены. S5 меняет только `MESSAGE` на
`sandbox-release smoke`. В S6 `tests/e2e/test_smoke.py` проверяет точный корневой
ответ реального процесса литералом, не импортируя ожидаемую константу приложения.
OpenAPI не должен заставлять scaffold менять сообщение раньше S5.

Сервер сопоставляет точные `self.path`: `/` и `/healthz` без query string;
все остальные GET request targets возвращают 404 JSON. OpenAPI перечисляет
контрольный неизвестный путь; общее правило для всех остальных путей находится
в описании API и `SPEC.md#http`. Другие методы вне smoke-контракта.

Проверки без секретов и внешних зависимостей:

```sh
python -m unittest discover -s tests/contract -v
python -m unittest discover -s tests/e2e -v
```

Conductor выполняет их в Compose `dev` согласно `tasks.yaml`. Финальное демо
через port-forward проверяет health, точный корень и неизвестный путь на нужной
развёрнутой ревизии, а также `application/json` у всех трёх ответов.
