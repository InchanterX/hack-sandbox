# Контракты sandbox-repair

- [openapi.yaml](openapi.yaml) — OpenAPI 3.1 итогового HTTP API, точные JSON-схемы
  и примеры. Расширение `x-unknown-get-response` задаёт 404 для любого GET,
  чей request target не равен `/` или `/healthz`; отдельного catch-all endpoint нет.
- [types.py](types.py) — общие типы Python 3.14 (`TypedDict`, `Literal`) для
  трёх ответов. Это описание wire format, без новой runtime-зависимости или
  требования импортировать типы в существующий сервер.
- [schema.sql](schema.sql) — явное отсутствие БД, таблиц и миграций;
  файл содержит только комментарии и не требует SQL-сервиса.

Все ответы API имеют `Content-Type: application/json`, точный набор полей и
`Content-Length` по байтам тела. Пробелы и порядок ключей незначимы. Нет auth,
тел запросов, поддерживаемых query-параметров, внешних API или секретов.
Сервер буквально сравнивает request target: query, trailing slash и любой
другой неизвестный путь дают 404. Другие HTTP-методы вне smoke-контракта.

Контракты описывают состояние **после S5**: корень возвращает
`{"message":"sandbox-repair smoke"}`. Исходный `seed` разрешён только на
локальном S4, пока сохраняется существующая реализация; не является release
контрактом. S4 сохраняет проверки `/healthz` и `/not-a-route` в
`tests/contract/test_http.py`, затем `tests/contract/**` заморожены.
В S6 существующая процессная проверка `tests/e2e/test_smoke.py` усиливается
точным сравнением корня и проверкой статуса / Content-Type здоровья и корня.

Полное владение файлами, этапы и исключения из общего шаблона:
[SPEC.md](../SPEC.md). Новые БД, frontend, AI и публичные маршруты не создаются.
